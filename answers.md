## Вопрос 1. Какие три основные области работы с файлами в Git (рабочая папка, индекс, репозиторий) и чем они отличаются?
Три основные области работы с файлами в Git: 
рабочая папка – локальный репозиторий на компьютере;
индекс – промежуточная зона между рабочей папкой и репозиторием;
репозиторий – хранилище со всеми файлами проекта.

## Вопрос 2. Что происходит при выполнении команд git add, git commit и git push
git add - добавление изменений в индекс;
git commit - отправка коммита;
git push - отправка изменений в ветку на удаленный репозиторий;

## Вопрос 3. Почему важно писать информативные сообщения к коммитам а не просто "исправление" или "update"?
Чтобы мне и другим членам команды (разрабочтикам) было понятно, какие изменения были внесены.

## Вопрос 4. Чем отличается git add имя_файла от git add .? В каких случаях лучше использовать каждый вариант?
git add имя_файла доабвлеяет в индекс конкретный измененнный файл, а git add . – все изменения. Первую команду лучше использовать, когда нужно закоммитить конкретные изменения, вторую – когда нужно закоммитить все изменения.

## Вопрос 5. Что показывает команда git status и как меняется ее вывод на разных этапах работы?
Она показывает, какие изменения были внесены с помощью команд git add и git commit

## Вопрос 6. Для чего нужна команда git remote add origin URL и что означает слово "origin"?
Команда связывает локальный репозиторий (на компьютере) с удаленным (на сервере). Origin это краткое имя сервера.

## Вопрос 7. Зачем нужен флаг -u в команде git push -u origin main при первой отправке изменений?
Флаг -u в команде git push -u origin main связывает локальную ветку main с удалённой. Последущие пуши не потребуют обозначения ветки, т.к. она уже будет задана.

## Вопрос 8. Что такое ветка (branch) по умолчанию и какая у вас создалась (main или master)? Почему это важно?
Это ветка, которая создаётся автоматически при инициализации репозитория. У меня создалась ветка main. Ветки нужны для разделения потоков внесения изменений в проект, ветка по умолчанию позволяет вносить изменения уже с момента инициализации репозитория (прежде конечно нужно индексировать их и запушить).

## Вопрос 9. Как просмотреть историю коммитов и какую информацию о каждом коммите вы видите?
Историю коммитов можно посмотреть через команду git log или на гитхабе через вкладку со всеми коммитами. В каждом коммите содержится уникальный идентификатор, автор и дата коммита, а также его описание.

## Вопрос 10. Что произойдет, если сделать изменения в файле, но не выполнить git add перед git commit?
Коммит создастся, но без изменений. Git закоммитит только то, что уже лежит в индексе.
