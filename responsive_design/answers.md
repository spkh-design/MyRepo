## Вопрос 1. Что такое Viewport meta tag и почему он важен для адаптивного дизайна?
Это тег <meta name="viewport" content="width=device-width, initial-scale=1">. Он сообщает браузеру, что ширина страницы равна ширине экрана устройства, а масштаб — 1:1. Без него мобильные браузеры рендерят страницу в условной «десктопной» ширине (~980px) и затем масштабируют её, из-за чего медиа-запросы и адаптивные стили не работают корректно.

## Вопрос 2. Какие основные подходы к созданию адаптивных макетов вы использовали в работе (Fluid, Adaptive, Responsive)?
- Fluid — резиновая вёрстка: размеры в процентах/fr, макет плавно тянется без брейкпоинтов.
- Adaptive — фиксированные макеты под конкретные устройства, переключаются через медиа-запросы.
- Responsive — сочетание: резиновая основа + брейкпоинты, где макет заметно перестраивается. Чаще всего использую Responsive: flex/grid + clamp() + несколько @media.

## Вопрос 3. Как работает Mobile First подход и в чем его преимущества перед Desktop First?
Стили пишутся сначала для мобильных, затем усложняются через min-width. Преимущества: меньше кода для мобильных (базовые стили простые), нет лишних переопределений, лучше производительность на слабых устройствах, проще поддерживать, соответствует современному трафику (большинство — мобильные).

## Вопрос 4. Какие единицы измерения наиболее предпочтительны для адаптивной верстки и почему (%, rem, em, vw/vh)?
- % — для ширин контейнеров и гибких блоков;
- rem — для типографики и отступов: привязаны к корневому шрифту, не зависят от вложенности, уважают настройки пользователя;
- em — для отступов внутри компонента, зависящих от его шрифта;
- vw/vh — для секций на всю высоту экрана, но осторожно (на мобильных vh скачет из-за адресной строки);
- clamp()/min()/max() — для плавной адаптации без брейкпоинтов.

## Вопрос 5. Как функция clamp() помогает создавать адаптивную типографику?
clamp(min, preferred, max) задаёт значение с нижней и верхней границей, а между ними — плавно меняющееся. Пример:

font-size: clamp(1rem, 2.5vw, 2rem);

Шрифт не станет меньше 1rem и больше 2rem, а между ними масштабируется вместе с шириной экрана. Убирает необходимость в медиа-запросах для типографики.

## Вопрос 6. Какие основные брейкпоинты вы использовали и как определили эти значения?
Обычно: 480px (крупные телефоны), 768px (планшеты), 1024px (небольшие ноутбуки), 1280px+ (десктоп). Определяю не по устройствам, а по контенту: сужаю окно и смотрю, где макет «ломается» — там и ставлю брейкпоинт. Это делает вёрстку устойчивой к любым экранам, а не только к популярным.

## Вопрос 7. Как медиа-запросы @media помогают создавать адаптивные стили? Приведите пример синтаксиса.
Позволяют применять CSS-правила при определённых условиях (ширина, ориентация, плотность пикселей и т.д.).

@media (min-width: 768px) {
  .container { display: flex; gap: 24px; }
}

Стили внутри сработают только при ширине экрана от 768px.

## Вопрос 8. В чем разница между max-width и min-width в медиа-запросах и когда использовать каждый?
max-width — стили применяются при ширине до указанной (Desktop First, «сверху вниз»). min-width — при ширине от указанной (Mobile First, «снизу вверх»). Предпочтительнее min-width: базовые стили для мобильных, затем наращивание — меньше переопределений и конфликтов.

## Вопрос 9. Как сделать изображения адаптивными и какие CSS-свойства для этого используются?

img {
  max-width: 100%;
  height: auto;
  display: block;
}

max-width: 100% не даёт картинке вылезти за контейнер, height: auto сохраняет пропорции. Дополнительно: srcset/sizes для разных разрешений, <picture> для арт-дирекшена, object-fit: cover для кадрирования.

## Вопрос 10. Какие инструменты браузера помогают тестировать и отлаживать адаптивный дизайн?
DevTools (F12): режим Device Toolbar (Ctrl+Shift+M) — выбор устройств, произвольные размеры, эмуляция touch и DPR. Также: инспектор для проверки flex/grid-оверлеев, панель Computed для итоговых значений, Lighthouse для аудита, эмуляция медленной сети и троттлинг CPU. Плюс тесты на реальных устройствах через BrowserStack/LambdaTest.
