## Вопрос 1. В чем разница между innerHTML и textContent и когда следует использовать каждый метод?
innerHTML читает и записывает HTML-разметку: при чтении возвращает сериализованный HTML потомков, при записи парсит строку и создаёт элементы. Это удобно для вставки разметки, но опасно: пользовательские данные могут привести к XSS-инъекциям, а парсинг медленнее. textContent читает и записывает только текст: при записи всё содержимое заменяется текстовой нодой, теги не интерпретируются, поэтому это безопасный способ вывести пользовательские данные. Использовать innerHTML – когда нужна именно разметка и она доверенная (или очищена через sanitizer); textContent – для обычного текста, когда важна безопасность и производительность. Для вставки HTML из ненадёжного источника – только с санитайзером (DOMPurify) или через textContent.

## Вопрос 2. Как работает делегирование событий (event delegation) и какие преимущества оно дает при работе с динамическими элементами?
Делегирование – приём, при котором обработчик вешается не на каждый элемент, а на их общего предка. Благодаря всплытию событие от дочернего элемента поднимается вверх, и обработчик на контейнере определяет, какой элемент был целью (event.target.closest('селектор')), и выполняет нужную логику. Преимущества: работает для элементов, добавленных в DOM позже (динамические элементы), не нужно вешать/снимать обработчики при добавлении и удалении; меньше обработчиков – меньше памяти и накладных расходов; проще поддерживать. Ограничения: не все события всплывают (например, focus, blur – но есть focusin/focusout), нужна аккуратная проверка target, чтобы не срабатывать на вложенных элементах.

## Вопрос 3. Какие методы используются для поиска элементов в DOM и в чем разница между getElementById, querySelector и querySelectorAll?
getElementById(id) ищет один элемент по id, самый быстрый, возвращает Element или null; id должен быть уникальным. querySelector(селектор) принимает любой CSS-селектор и возвращает первый подходящий элемент (или null), работает от document или от элемента; универсален, но чуть медленнее getElementById. querySelectorAll(селектор) возвращает статический NodeList всех подходящих элементов (не живой: не обновляется при изменении DOM); по нему можно итерироваться через forEach. Также есть getElementsByClassName и getElementsByTagName – возвращают живые HTMLCollection, которые обновляются автоматически. Выбор: id – getElementById; сложные селекторы – querySelector(All); живые коллекции нужны редко.

## Вопрос 4. Как предотвратить стандартное поведение элемента при обработке событий и когда это необходимо?
Стандартное поведение отменяется через event.preventDefault() внутри обработчика: например, для ссылки – переход по href, для формы – отправка и перезагрузка страницы, для чекбокса – переключение, для контекстного меню – его показ. Необходимо, когда поведение обрабатывается вручную: валидация и отправка формы через fetch/AJAX, SPA-навигация по ссылкам без перезагрузки, кастомные drag-and-drop и контекстные меню, ограничение ввода. Важно: preventDefault не останавливает всплытие (для этого stopPropagation), а отменить можно только отменяемое событие (event.cancelable). Злоупотреблять не стоит – ломает ожидаемое поведение и доступность.

## Вопрос 5. В чем разница между classList.add() и className для работы с CSS классами?
className – это строка со всеми классами элемента через пробел: чтобы добавить класс, нужно прочитать строку, изменить её и записать обратно (el.className += ' active'), легко случайно удалить или продублировать классы, затереть существующие. classList – объект-коллекция с методами add, remove, toggle, contains, replace: точечные операции без ручной работы со строкой, автоматически не допускает дубликатов, читаемее. classList предпочтителен почти всегда; className удобен, когда нужно полностью заменить набор классов одной строкой или получить все классы сразу. classList поддерживается всеми современными браузерами; для очень старых есть полифиллы.

## Вопрос 6. Как создать новый элемент и добавить его в DOM несколькими способами? Какой способ наиболее эффективен?
Способы: document.createElement('div') + настройка свойств/текста + parent.appendChild(el) или parent.append(el); вставка через innerHTML/insertAdjacentHTML с разметкой; клонирование шаблона (template.content.cloneNode(true)); создание через конструктор (new Option(), new Image()); использование DocumentFragment для сборки нескольких элементов. Наиболее эффективен и безопасен вариант с createElement (+ DocumentFragment при вставке множества узлов): не требует парсинга HTML, не создаёт XSS-рисков, позволяет настраивать элементы до вставки (меньше reflow). Вставку в DOM лучше делать один раз – собрать всё в фрагменте и вставить фрагмент целиком. innerHTML уместен для доверенной статичной разметки, но медленнее и небезопасен с данными пользователя.

## Вопрос 7. Что такое всплытие событий (event bubbling) и как работает метод stopPropagation()?
Всплытие – фаза распространения события от целевого элемента вверх по дереву к предкам (target → parent → ... → document → window). Событие сначала идёт по фазе захвата (capture) сверху вниз, затем на цели, затем всплывает. Обработчики по умолчанию срабатывают на фазе всплытия. stopPropagation() останавливает дальнейшее распространение события: обработчики на предках не вызовутся (но остальные обработчики на текущем элементе выполнятся). stopImmediatePropagation() дополнительно отменяет оставшиеся обработчики на том же элементе. Использовать осторожно: остановка всплытия ломает делегирование и другие обработчики, часто достаточно preventDefault или проверки target. Всплытие лежит в основе делегирования событий.

## Вопрос 8. Как получить данные из формы и в чем разница между методами сбора form data?
Способы: обратиться к элементам формы по name (form.elements.name.value, form.name.value) – просто, но нужно вручную собирать объект; new FormData(form) – собирает все успешные (не disabled, с name) поля в пары ключ-значение, поддерживает файлы, удобно для отправки через fetch; form.elements – коллекция всех элементов формы; сериализация через URLSearchParams(new FormData(form)) – для query-строки; сторонние библиотеки (serialize). Разница: прямое обращение даёт точечный доступ и значения в нужном типе, но не масштабируется; FormData автоматически учитывает правила формы (disabled, checkbox, multiple select, файлы) и предназначен для отправки, но не даёт объект напрямую (нужен Object.fromEntries с оговорками для повторяющихся имён и файлов). Для сложных форм часто комбинируют: FormData для отправки, ручной сбор для валидации.

## Вопрос 9. Какие события используются для обработки ввода данных и в чем разница между input, change и keyup?
input срабатывает при каждом изменении значения (ввод символа, вставка, удаление, автозаполнение) – лучше всего для «живой» валидации, счётчиков символов, поиска. change срабатывает, когда значение зафиксировано и элемент теряет фокус (для текстовых полей) или сразу при изменении (для select, checkbox, radio, range) – удобно для применения выбора, не мешая вводу. keyup срабатывает при отпускании клавиши и даёт информацию о клавише, но не отражает вставку мышью, автозаполнение, IME-ввод и удержание клавиши; для отслеживания значения хуже, чем input. Также есть keydown/keypress (нажатие) и beforeinput. Рекомендация: значение – через input, фиксация выбора – change, клавиатурные сценарии (Enter, Esc) – keydown.

## Вопрос 10. Как оптимизировать производительность при частых манипуляциях с DOM?
Минимизировать количество обращений к DOM: собирать изменения и вставлять один раз, использовать DocumentFragment, клонировать шаблоны, настраивать элементы до вставки. Батчить чтение и запись: сначала все чтения (offsetWidth, getBoundingClientRect), потом все записи, чтобы избежать layout thrashing; для визуальных обновлений – requestAnimationFrame. Использовать делегирование событий вместо множества обработчиков; снимать обработчики при удалении элементов. Для больших списков – виртуализация (рендер только видимых), пагинация, ленивая загрузка. Кэшировать ссылки на элементы, избегать innerHTML в цикле, применять CSS-классы вместо инлайн-стилей, CSS-анимации (transform/opacity) вместо изменения layout-свойств. Для тяжёлых вычислений – Web Workers, для частых событий – debounce/throttle.
